## 3. Agents: Concept and Implementation

### What Is an Agent?

- An **agent is an autonomous system that can make decisions to use tools based on user input**.
- Traditional LLMs provide outputs based solely on input but cannot fetch **real-time or external dynamic data**.
- Agents integrate with **external tools or APIs** (e.g., weather API, search engines) to retrieve context-sensitive data unavailable in pre-trained LLMs.

### Basic Agent Workflow:

1. User inputs query.
2. Agent decides if an external tool is needed.
3. Agent routes query to the appropriate tool.
4. Tool returns context.
5. LLM combines context and generates output.

This enables response to questions like "What is today's AI news?" by calling Google Search or news API tools.

### LangChain v1 Agent Creation

- Use `langchain.agents.create_agent()` specifying:
  - `model`: The underlying LLM (e.g., GPT-5).
  - `tools`: Functions wrapped as tools (can be empty initially).
  - Optional system prompt for assistant behavior.

### Example Tool Integration

```python
from langchain.tools import tool

@tool
def get_weather(city: str) -> str:
    """Get the weather for a city."""
    return f"The weather in {city} is sunny"
```

- Attach tools to the agent so that **LLM intelligently calls the correct tool based on query**.
- Agent invocation expects inputs as **messages dictionaries** with roles (`user`, etc.).
- The agent’s internal reasoning can be verbose (debug info enabled optionally).

### Model Invocation

- Use `model.invoke()` with a message or list of messages.
- Supports passing **plain text prompts** or structured **message objects**.
- Outputs an AI-generated response object with `.content`.

## 5. Streaming vs Batch Processing

### Streaming Output:

- Enables **progressive output display** while the LLM generates tokens.
- Greatly improves user experience for long completions.
- Implemented via `model.stream()`, which returns a generator yielding chunks.
- Sample code prints chunks with flush and custom delimiters for clarity.

### Batch Processing:

- Sends multiple independent prompts simultaneously.
- Improves performance and reduces latency for bulk queries.
- Invoked via `model.batch()` with a list of inputs.
- Supports concurrency limits (`max_concurrency`) for controlling parallel requests.

## 6. Tools: Definition, Creation, and Execution Loop

### What Are Tools?

- Tools encapsulate external functions/APIs that an agent can call to supplement LLM knowledge.
- Defined as Python functions decorated with `@tool` from `langchain.tools`.
- Include a **name, argument types, a docstring/definition** describing purpose.

### Tool Creation Example

```python
from langchain.tools import tool

@tool
def get_weather(location: str) -> str:
    """Get weather at a location."""
    return f"Sunny in {location}"
```

### Binding Tools to LLMs

- Tools can be **bound directly to models** via `model.bind_tools()`.
- Alternatively, agents can be created with specified tools via `create_agent()`.

### Tool Execution Loop

- Handles interaction between agent and tools dynamically.
- When the agent decides to call a tool, it generates a `tool_call` message.
- The tool executes (e.g., fetches data) and returns context.
- Context is appended to the message stream and used by the LLM to generate final output.

---

## 7. Messages: Types and Usage in LangChain

**Messages are the fundamental units of context in LangChain.** Each message contains:

- **Role**: Identifies origin/type (`system`, `human`, `AI`, `tool`).
- **Content**: The text or data payload.
- **Metadata**: Optional tracing/usage info.

### Message Types

| Message Type     | Description                                            |
|-----------------|--------------------------------------------------------|
| **System Message** | Instructions guiding LLM behavior (e.g., persona).    |
| **Human Message**  | User input or prompts.                                 |
| **AI Message**     | LLM-generated output, including tool calls metadata. |
| **Tool Message**   | Output from a tool invoked by the agent.              |

### Using Messages in Code

- You can pass a **list of messages** representing conversation history.
- Example: setting system role as poetry expert, human role requesting a poem.
- Metadata can be attached to messages for analysis or user-tracking.

## 8. Structured Output: Enforcing Schema on LLM Responses

### Motivation

- Ensuring LLM responses adhere to **predetermined structured formats** enables downstream automation.
- Useful in production applications needing predictable data formats.

### Supported Schema Methods

| Method       | Description                                                                                   | Validation           |
|--------------|-----------------------------------------------------------------------------------------------|----------------------|
| **Pydantic** (recommended) | Robust: supports field validation, descriptions, nested structures                     | Full runtime validation |
| **TypedDict**            | Simple Python typing-based dictionaries; no runtime validation                           | None                 |
| **DataClasses**          | Python data classes, typically less used here but supported                              | Partial              |

---

### Pydantic Example:

```python
from pydantic import BaseModel, Field

class Movie(BaseModel):
    title: str = Field(..., description="Title of the movie")
    year: int = Field(..., description="Release year")
    director: str = Field(..., description="Movie director")
    rating: float = Field(..., description="Movie rating out of 10")
```

- LangChain can wrap models with this schema to **parse outputs and validate fields**.
- Invalid field types raise errors.
- Supports **nested structures**, e.g., a list of actors within Movie:

```python
class Actor(BaseModel):
    name: str
    role: str

class MovieDetails(BaseModel):
    title: str
    year: int
    cast: list[Actor]
    genres: list[str]
    budget: float = Field(None, description="Budget in million USD")
```

---

### TypedDict Alternative:

- Simpler, uses Python type hints without required runtime validation.
- Suited for cases where strict schema enforcement is less critical.

```python
from typing import TypedDict, Annotated

class MovieDict(TypedDict):
    title: Annotated[str, "Title of the movie"]
    year: Annotated[int, "Release year"]
    director: Annotated[str, "Director of the movie"]
    rating: Annotated[float, "Movie rating out of 10"]
```

- Can be used similarly with LangChain's `with_structured_output()`.

## Detailed Summary

### Introduction to Generative AI and Language Models
The course begins by defining **generative AI** as AI that creates new content (text, images, audio, code), powered by **large language models (LLMs)** like GPT-3/4, Claude, and Google Gemini. It distinguishes generative AI from traditional AI systems that use statistical ML models (e.g., XGBoost, random forest) primarily for classification tasks, not content generation.

Transformers, introduced by the seminal "Attention is All You Need" paper, underpin LLMs. These models generate content by predicting the next token in a sequence using self-attention mechanisms, leveraging vast datasets. Sampling parameters like temperature, top-K, and top-P affect creativity and randomness. The course also explains tokens and the importance of the **context window**—the maximum tokens an LLM can handle in one prompt (ranging from thousands to over a million tokens in modern models).

### Hands-On with LangChain and LLM API Calls
Viewers learn how to set up API keys with Google AI Studio and Grok Cloud, and programmatically call LLMs to generate responses. Basic calls cover text generation with or without system prompts for constrained answers, controlling token sampling with parameters like temperature.

They then build a simple health data analysis app which extracts medical test values from text blood reports, classifies them as high/low/normal, and provides personalized dietary recommendations. This introduces **prompt engineering** and workflows where multiple sequential LLM calls perform subtasks.

### Retrieval-Augmented Generation (RAG)
Large private data (e.g., company HR policies) cannot be fully consumed by LLMs due to token limits and cost. RAG addresses this by:

1. Chunking documents into manageable pieces with overlaps to retain context.
2. Converting chunks into **vector embeddings** which represent semantic meaning.
3. Storing embeddings in **vector databases** like ChromaDB.
4. Upon a user query, embedding the query, retrieving relevant chunks by semantic similarity, and prompting the LLM with only those chunks.

This architecture increases answer accuracy by grounding in reliable sources while decreasing token usage and associated API costs.

### Vector Database Basics
The course demonstrates vector database usage with ChromaDB, showing how documents and queries are embedded, stored, and retrieved by meaning rather than exact keyword matches, enabling contextually relevant search results.

### Building a Simple Sales Agent — Tools, Agents, and Memory
Learners create an agent that accesses product and reviews data from Python dictionaries, showcasing:

- Tool definition with descriptive docstrings guiding the agent on what each function does.
- Agent autonomously deciding which tool to invoke based on the question intent, enabled by LLM interpretation.
- Adding memory so agents can reference prior conversation context, allowing multi-turn interaction similar to ChatGPT.

Multiple tools can co-exist, and the agent dynamically calls appropriate ones. The agent demonstrates **react loops**—reasoning, acting, and observing—to accomplish complex tasks.

### Multi-Agent Systems and Agency Levels
More advanced systems comprise multiple agents focusing on subtasks, e.g., product search, checkout, review analysis. Levels of agency vary:

- Low: ChatGPT-like apps answering questions with limited external tool access.
- Medium: Automation platforms like Zapier integrating APIs.
- High: Cloud Code orchestrates multi-step autonomous coding.
- Very High: Open Claw runs autonomous systems with broad tool access but reduced predictability.

Trade-offs exist between agency and control; high autonomy can lead to unpredictable behavior.

### Multimodal AI Use Cases
Multimodal LLMs accept images/audio alongside text. The video shows:

- Using a vision-capable LLM (Grok’s Lama for Scout) to extract structured data from images of blood reports.
- Encoding images as base64 strings for model consumption.
- Combining multi-input analysis with downstream tools for health advice generation.

This expands AI applications in domains with mixed data types, such as healthcare insurance.

### AI Agent Evaluation and Safety
Because AI outputs are probabilistic, evaluation requires alternatives to exact matching. Frameworks use semantic similarity (e.g., cosine similarity), latency, cost metrics, and toxicity scanning.

Guardrails mitigate risks like hallucinations, PII leaks, jailbreak attacks, and out-of-scope responses by middleware filters, prompt restrictions, and content redaction.

The Air Canada chatbot lawsuit and Chipotle bot misuse highlight the necessity of robust safeguards.
